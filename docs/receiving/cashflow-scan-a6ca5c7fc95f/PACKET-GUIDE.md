# Household cashflow — saved-file receiving packet v1

This packet makes the published cashflow optimization directly reproducible with
fictional saved JSON. Run one command to compare the original and candidate on
173 requests. It includes the exact emitted calculation modules, build/test
source subsets, source custody, the author's raw benchmark and maintained-test
logs, and Delivery's independent source-informed receiving evidence.

The qualification is a source and saved-file workflow result. Canonical
integration and installed adoption remain with `estate-ce7eb129730f` and
`estate-61749b0088e2`. The held issue #20 report receiver is outside this packet.

## Run the saved-file course

Use Node **20 or later**; the recorded run used **24.19.0**. Extract the ZIP, open
a terminal in its `cashflow-saved-file-v1` directory, and run:

```sh
node source/after/docs/receiving/cashflow-scan-a6ca5c7fc95f/receive-saved-cashflow.mjs runtime/before runtime/after ../NEW-cashflow-result
```

The output parent must already exist and `NEW-cashflow-result` must not. You can
substitute another new output path, quoted if it contains spaces. The command
requires Node's standard library only. It does not install packages, contact a
service or read a household's actual ledger. It creates 35 fictional saved files
inside its own new result directory and retains them for inspection.

Expected summary: **173 requests, 127 returned results, 46 refusals, 35 saved files
unchanged**. Each version loads each requested saved JSON through its actual
`LedgerStore.load()` and calls `cashflowTrend()`. Complete serialized results or
exact error class/message must match. The source files, saved bytes and saved
modification times must remain unchanged; a missing ledger must remain absent.

The output includes `receipt.json`, the request list, and a manually checked
three-month result. A fresh run records its source files' current modification
times, so the new receipt hash can differ from the original receipt while the
complete outcomes and source hashes match.

## Inspect a small example

`fictional-example/ledger.json` contains four fictional transactions across
December 2024 to February 2025. `expected-cashflow.json` is the complete candidate
result for USD. Income is 1100, expenses 550 and net 550 in minor units;

## Build from source

In each of `source/before` and `source/after`, use the unchanged lockfile:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
```

These optional commands install the declared dependencies, compile TypeScript,
and run the maintained tests. Run them in the extracted packet directories.
They are separate from the dependency-free saved-file command above. After
building both versions, the same receiver can compare their `dist/src`
directories in place of the included `runtime/before` and `runtime/after`.

For the author's optional benchmark with the supplied emitted modules, run from
the packet root:

```sh
node source/after/docs/receiving/cashflow-scan-a6ca5c7fc95f/benchmark.mjs runtime/before runtime/after
```

The recorded largest synthetic case has 60,000 records over 120 months. The
author measured calculation plus serialization at 122.718 → 25.590 ms and the
full saved-file workflow at 213.087 → 139.473 ms. Each value is the median of
seven samples after warmup; complete responses match. The 12,000-record,
12-month saved-file case did not improve measurably. These are local synthetic
measurements, not installed service or hosted MCP latency. The packet preserves
the raw samples and their limitations; Delivery did not duplicate this benchmark.
