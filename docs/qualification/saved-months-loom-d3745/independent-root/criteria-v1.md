empty stdout and a nonempty diagnostic; no exact diagnostic wording claim.

The receiver builds an isolated runtime projection containing only the two
offered new runtime modules and the exact original native ledger module. It
uses Node24's standard stripTypeScriptTypes transform, writing dist/src/ledger.js
and a local type:module package marker before execution. This is explicitly
not npm ci, tsc, a project-wide build, MCP activation or an installed workflow.
The candidate source remains untouched. All four offered source hashes must
match the author manifest before and after; runtime, controls, fixtures and
the unrelated occupied sentinel must remain byte/mode/link identical.

from the saved mixed output and calls unchanged validateLedgerData/monthlySummary
on those exact original bytes. Its complete expected JSON is separately frozen.
It verifies direct use of the discovered key with the existing calculation;
all amounts are authored fictional input and no financial decision is made.

Each child gets prospectively created stdout/stderr files, an explicit timeout,
an isolated process group and closure accounting. No shell evaluation, Store,
network dependency acquisition, output-file option or product retry. Failures
remain failures; this course is not silently replayed or widened. Read-only
postprocessing compares exact original artifacts and does not rerun the product.
